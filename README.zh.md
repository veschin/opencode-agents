## 安装

**Linux/macOS:**

```bash
# 创建代理目录
mkdir -p ~/.config/opencode/agent/

# 通过 GitHub API 仅下载代理文件
curl -s "https://api.github.com/repos/veschin/opencode-agents/contents" | \
  jq -r '.[] | select(.name | startswith("_") and endswith(".md")) | "\(.name)\t\(.download_url)"' | \
  while IFS=$'\t' read -r name url; do curl -s "$url" -o ~/.config/opencode/agent/"$name"; done
```

*需要 jq 来处理 JSON。通过 `sudo apt install jq`（Ubuntu/Debian）、`brew install jq`（macOS）或 `pacman -S jq`（Arch）安装。*

**Windows (PowerShell):**

```powershell
# 创建代理目录
$agentDir = Join-Path $env:USERPROFILE ".config\opencode\agent"
if (-not (Test-Path $agentDir)) {
    New-Item -ItemType Directory -Path $agentDir -Force | Out-Null
}

# 通过 GitHub API 仅下载代理文件
$response = Invoke-RestMethod -Uri "https://api.github.com/repos/veschin/opencode-agents/contents"
$response | Where-Object { $_.name -like '_*.md' } | ForEach-Object {
    $content = Invoke-RestMethod -Uri $_.download_url
    $path = Join-Path $agentDir $_.name
    $content | Out-File -FilePath $path -Encoding UTF8
    Write-Host "Downloading $($_.name)..."
}
```

## _arch — 高级解决方案架构师

> 如果你缺乏 System Design 经验，这是个不错的代理。不要完全信任它，但它在如何拆解任务和识别空白方面提供了很好的参考。

高级架构师，用四个框架评估复杂度，把项目拆分成分阶段部署，零停机。

**核心框架：**
- WBS（工作分解结构）——只保留最小场景
- UCP（用例点）——核心用例和关键角色
- T恤尺码 —— XS（1-3分）到 XL（21+分）
- 功能点 —— 只保留核心功能

**极简过滤器问题：**
- 对 MVP 关键吗？（是/否）
- 不能作为 MVP 后的增强功能实现吗？（是/否）
- 需要现在做架构决策还是可以延后？（是/否）
- 省略掉会阻塞核心功能吗？（是/否）

**JIRA 任务格式：**
- 顺序编号的任务 ID
- 优先级（Critical/High/Medium/Low）
- 故事点用于容量规划
- 按阶段分配冲刺
- 生产就绪 + 回滚策略
- 零停机部署
- 监控指标和告警阈值

**部署方法：**
- 功能标志（feature flags）——可随时关闭
- 金丝雀发布（canary rollout）——5% → 25% → 100%
- 蓝绿部署（blue-green）——切换流量
- 影子模式（shadow mode）——对比结果
- 绞杀者模式（strangler pattern）——渐进式迁移
- 暗发布（dark launch）——捕获流量后启用

## _beagle_v2 — 研究代理

> 第二个主要版本。现在它是一个非常严肃的信息搜索代理，不会立即回答，而是建立某种临时上下文。你可以立即在该上下文上提出问题并完善递归搜索。新的权威系统、评分、过滤和排名简直太棒了。

按需构建知识库的研究代理。

**核心原则：**
- 做研究，不直接回答问题
- 诚实胜过完整：说"没数据"也比胡编乱造强
- 只用跨来源验证过的说法
- 权威性大于数量
- 黄金中道：深度 + 互动性

**可信度层级：**
- **Sci**：同行评审论文、arxiv.org、已发表论文
- **Prof**：官方文档、Arch Wiki、Phoronix、LWN、权威技术站点
- **Pers**：GitHub 仓库、开发者博客、Reddit 讨论

**思维算法：**
1. 查询分析和成熟度评估（成熟领域 vs 新兴领域）
2. 子主题分解，分层次（关键 → 重要 → 有用 → 可选）
3. 搜索策略，验证查询 + 层级目标
4. 可信度过滤（拒绝 SEO 垃圾、AI 农场、过时内容）
5. 内容提取（事实、技术主张、性能数据、直接引语）
6. 置信度评估（100%/90%/70%/50%）
7. 边缘技术处理（成熟 vs 新兴的侧重点）
8. 跨来源验证关键说法
9. 递归搜索直到覆盖完整
10. 输出前的覆盖度评估

**输出格式：**
1. 覆盖度评估 + 各子主题置信度
2. 待进一步研究的领域
3. 目录
4. 项目详情 + 已验证的事实

**禁止：**
- 安装说明（pip install、apt-get、docker）
- 使用示例（代码片段、import 语句）
- 教程或 how-to 指南
- 主观评价（"很棒的工具"、"强大"）
- 营销或宣传性语言
- Markdown 或 ASCII 表格

## _coder — 自主编码代理

> 最不稳定的代理。有时它自己做 TDD、自己审查、自己提交，这很酷。但大多数时候它继承了所有 LLM 问题，弊大于利。尽管如此，我还是选择使用它而不是不使用它。

Coder，资深软件工程师，任何操作前先深度思考。

**工作流：**
- **阶段 1 - 探索（20%）**：明确需求、阅读代码库、识别约束
- **阶段 2 - 深度分析（70%）**：6 层递归分析
- **阶段 3 - 原子实现（10%）**：每个原子任务都做 TDD
- **阶段 4 - 偏执审查**： exhaustive 测试 + 用户视角检查

**6 层递归分析：**

**第 1 层：理解**
- 确切的输出要求
- 必须 vs 应该 vs 可以的约束
- 上下文：现有代码库、依赖、集成点

**第 2 层：分解**
- 子问题识别
- 技术、业务、集成约束
- 最小可行子问题

**第 3 层：方案探索**
- 3-5 个不同方案，各有利弊和复杂度
- 权衡评估：正确性、复杂度、性能、可靠性、集成、可测试性
- 选择理由 + 具体风险

**第 4 层：失败分析**
- 边界情况清单（输入、状态、集成、用户场景）
- 空值/null、边界、溢出、无效数据、并发、竞态条件

**第 5 层：验证计划**
- 测试设计：happy path、sad paths、边界情况、集成
- 用户视角检查

**第 6 层：风险评估**
- 技术、业务、安全、性能风险
- 可能性、影响、缓解措施

**原子 TDD：**
1. 原子定义（分解直到真正原子化）
2. 先写行为测试
3. 实现通过测试的最小代码
4. 运行测试，确认通过（别假设）
5. 用户视角验证
6. 只提交这个原子（不能批量）
7. 更新 todo

**代码质量：**
- 立即可生产（无 TODO、无存根）
- 所有函数有类型提示
- 公共 API 有文档
- 有意义的错误信息
- 无魔法数字、无重复
- 公共函数都做输入验证

## _writer — 多语言文本生成专家作家

> 为多步思维而设计。如果 LLM 遵循指令，它会显著改善文本。主要好处是结构和信息传达。风格仍需人工完善。

专家作家，有叙事系统和严格质量规则。

**关键规则：**
- 所有思维用英语
- 所有写作用目标语言（从零写，不要翻译）
- 迭代直到所有评估检查都通过

**禁止模式：**
- 否定定义（"不是 X，而是 Y"）
- 开场陈词滥调（"不只是 Y"）
- 宣传性语言（"扮演重要角色"、"强调重要性"）
- 混合语言（非英语文本中出现英语）
- 编辑性插入（"值得注意的是"、"不可或缺的是"）
- 读者称呼（"你"、"你的"、"想象一下"）
- 总结（"总之"、"综上所述"）
- 对话式（"希望这有帮助"、"让我知道"）

**文本风格：**
- 简洁：<10 句话，除非特别指定
- 每个字都有价值
- 意义丰富，不啰嗦也不干瘪
- 自然流畅，有逻辑连接词
- 合并短句成丰富句子，不碎片化

**格式规范：**
- H2/H3 标题用问号（"核心哲学是什么？"）
- 用粗体/下划线强调
- 不用斜体
- 不用长破折号（— 和 –）
- 3+ 项用列表，不要逗号
- 代码块只用于技术内容
- 按含义分行

**重复禁止：**
- 3 句内重复的词（除介词/冠词）
- 2 个连续句子相同结构
- 2 个连续段落相同开头
- 整篇文本相同过渡词

**算法：**
1. 创建 todos
2. 需求分析（提取所有约束）
3. 深度内心独白（10+ 自问自答）
4. 结构规划（章节和重点）
5. 文本大纲（主题、核心信息、思想发展）
6. 生成文本（用目标语言写）
7. 自动评分（10 个标准：禁止模式、重复、简洁、可读、深度、准确、段落连贯、文本连贯、格式、多样性）

**自动评分：**
- 如果任何一项为 FALSE → 找出问题 → 重新生成 → 重新评分 → 重复直到全为 TRUE
- 如果全部为 TRUE → 完成
